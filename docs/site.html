Introduction

Agents in Go, where everything is a plugin.

eipagent is a Go SDK for building AI agents. The core only loads plugins and routes calls between them. The agent loop, every model provider, tools, memory, middleware, sandboxes and security rules are plugins you can add, swap or remove, even while the agent runs.

Quickstart Run locally with Ollama GitHub
Simple

Generate, Stream, GenerateObject[T] and typed tools. One import for most apps.

Complete

Four providers, a middleware pack, durable threads, approvals, MCP, subagents, skills.

Secure by default

Pinned plugins, scoped permissions, a locked policy layer, a tamper-evident audit log.

Pluggable sandboxes

Agents start sandboxes for their tools, or run inside one with keys kept on the host.

Getting started

Installation

eipagent needs Go 1.27 or newer. The module is private for now, so clone it next to your project and point your go.mod at the checkout.

git clone https://github.com/ganeshdipdumbare/eipagent
cd my-app
go mod edit -require=eipagent@v0.0.0 -replace=eipagent=../eipagent
go mod tidy

Check that everything works. The test suite runs offline, using a mock model that needs no API key.

cd eipagent && go test ./...

Getting started

Quickstart

Pick a provider, export its key, and give your agent a tool. The model string is provider:model, and the matching provider plugin loads automatically.

export ANTHROPIC_API_KEY=sk-ant-...
# model: "anthropic:claude-sonnet-5-5"
export OPENAI_API_KEY=sk-...
# model: "openai:gpt-4.1"
export GEMINI_API_KEY=...
# model: "gemini:gemini-2.5-pro"
export DEEPSEEK_API_KEY=sk-...
# model: "deepseek:deepseek-chat"
ollama pull lfm3
# model: "ollama:lfm3"   (no key needed)
package main

import (
	"context"
	"fmt"
	"log"

	"eipagent"
)

type WeatherIn struct {
	City string `json:"city" desc:"city name"`
}

func main() {
	ctx := context.Background()

	weather := eipagent.Tool("weather", "Current weather for a city",
		func(ctx context.Context, in WeatherIn) (string, error) {
			return "18°C and light rain in " + in.City, nil
		})

	agent, err := eipagent.New(
		eipagent.WithModel("anthropic:claude-sonnet-5-5"),
		eipagent.WithInstructions("You are a concise travel assistant."),
		eipagent.WithTools(weather),
	)
	if err != nil {
		log.Fatal(err)
	}
	defer agent.Close()

	res, err := agent.Generate(ctx, "What's the weather in Lisbon?")
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(res.Text)
}

The model decides to call weather, the agent runs it, sends the result back, and returns the final answer. The argument schema comes from WeatherIn.

Getting started

Run locally with Ollama

Everything works with a local model. No API key is needed and nothing leaves your machine. The repo ships a runnable example with one demo per feature.

ollama pull lfm3
go run ./examples/ollama -demo text      # one prompt, one answer
go run ./examples/ollama -demo stream    # tokens as they arrive
go run ./examples/ollama -demo plugins   # add, update and remove plugins while it runs
go run ./examples/ollama                 # every demo

Use any model with -model qwen3.5:4b. Set OLLAMA_HOST to use Ollama on another machine. Demos that use tools work best with a tool-capable model of 4B parameters or more.

Foundations

Generating text

Generate runs the agent until it has an answer and returns everything that happened.

res, err := agent.Generate(ctx, "Summarize our refund policy in two sentences.",
	eipagent.Temperature(0.2),
	eipagent.MaxSteps(5),
)

res.Text          // the final answer
res.Steps         // each model call, with its tool results
res.ToolCalls()   // every tool call in the run
res.Usage         // input, output and total tokens
res.FinishReason  // stop | max_steps | interrupted | tool:<name>

For a one-off call without keeping an agent around, use eipagent.GenerateText(ctx, "openai:gpt-4.1", "Hello").

Foundations

Streaming

Stream returns right away. Range over text deltas, or over every event, then read the final result.

s := agent.Stream(ctx, "Write a haiku about Lisbon")
for delta := range s.Text() {
	fmt.Print(delta)
}
res, err := s.Result()
for e := range agent.Stream(ctx, "Plan my day").Events() {
	switch e.Type {
	case "text":
		fmt.Print(e.Text)
	case "tool_call":
		fmt.Println("\ncalling", e.ToolCall.Name)
	case "tool_result":
		fmt.Println("got", e.Result)
	}
}

Breaking out of a loop early is safe. The run still completes and Result() returns it.

Foundations

Tools

eipagent.Tool turns a typed Go function into a tool. The JSON Schema is derived from the input struct.

type SearchIn struct {
	Query string `json:"query" desc:"what to look for"`
	Limit int    `json:"limit,omitempty" desc:"max results"`
	Sort  string `json:"sort,omitempty" enum:"relevance,date"`
}

search := eipagent.Tool("search_tickets", "Search support tickets",
	func(ctx context.Context, in SearchIn) ([]Ticket, error) {
		return db.Search(ctx, in.Query, in.Limit)
	})

agent, _ := eipagent.New(eipagent.WithModel("openai:gpt-4.1"), eipagent.WithTools(search))
  • Tags: json names the field, desc describes it, and enum restricts its values. A field tagged omitempty or declared as a pointer is optional.
  • Return values: a string goes to the model as it is. Anything else is sent as JSON.
  • Errors: a returned error is shown to the model so it can recover. Return sdk.Fatal(err) to abort the run instead.
  • Hints: eipagent.ReadOnly(tool) marks a tool as side-effect free, and eipagent.WithMeta(tool, "risk", "high") flags a risky one. Policy and approval rules use these hints.
  • Per-run tools: eipagent.RunTools(...) adds tools for a single call.

Foundations

Structured output

GenerateObject[T] returns a typed value instead of text.

type Trip struct {
	City    string   `json:"city"`
	Packing []string `json:"packing" desc:"things to pack"`
	Budget  int      `json:"budget_eur,omitempty"`
}

trip, err := eipagent.GenerateObject[Trip](ctx, agent, "Plan what to pack for Lisbon.")
fmt.Println(trip.City, trip.Packing)

How the schema reaches the model depends on the provider:

  • OpenAI and Gemini use their native JSON-schema mode.
  • Anthropic gets the schema as a forced tool.
  • DeepSeek and Groq use JSON mode, with the schema in the prompt.

If the reply doesn't parse, eipagent asks the model once to fix it, then returns eipagent.ErrNoObject.

Foundations

Threads and memory

A thread is a conversation that persists between calls. It lives in a checkpointer plugin, which is in memory by default.

agent, _ := eipagent.New(
	eipagent.WithModel("openai:gpt-4.1"),
	eipagent.WithPlugin("checkpoint_file", map[string]any{"dir": ".eipagent/threads"}), // or checkpoint_sql
)

th := agent.Thread("customer-42")
th.Generate(ctx, "My name is Ada.")
res, _ := th.Generate(ctx, "What's my name?") // remembers the earlier turn
msgs, _ := th.Messages(ctx)

Long-term memory lasts across threads. Load store_inmem, store_file or store_sql, plus memory_store. The model then gets remember and recall tools, kept separately for each user.

agent, _ := eipagent.New(
	eipagent.WithModel("openai:gpt-4.1"),
	eipagent.WithPlugins("store_file", "memory_store"),
	eipagent.WithUser("ada"),
)

Long conversations stay inside the context window with mw_summarize. It summarizes older messages and keeps the most recent ones word for word.

Foundations

Human in the loop

Pause before risky tools run. A person approves, edits, rejects or answers, and the run continues from where it stopped.

agent, _ := eipagent.New(
	eipagent.WithModel("openai:gpt-4.1"),
	eipagent.WithTools(refund),
	eipagent.WithPlugin("mw_hitl", map[string]any{
		"interrupt_on": map[string]any{"refund": true}, // or {"non_readonly": true}
	}),
)

th := agent.Thread("ticket-981")
res, _ := th.Generate(ctx, "Refund order A-17")
for res.Interrupted() {
	in := res.Interrupts[0]
	fmt.Println("approve?", in.Message, in.ToolCall.Args)
	res, _ = th.Resume(ctx, eipagent.Approve(in.ID))
	// or eipagent.Reject(id, why), eipagent.Edit(id, args), eipagent.Respond(id, text)
}
Tip

The pause is saved in the checkpointer. With checkpoint_sql, another process can resume it, hours later and on a different machine.

To decide right away instead, for example by prompting in a CLI, pass eipagent.WithApprover(func(ctx, in) (*Decision, error)).

To let a model screen calls before a person sees them, add mw_auto_review. A reviewer model approves, denies or escalates each call.

eipagent.WithPlugin("mw_auto_review", map[string]any{"model": "anthropic:claude-haiku-5-5"})

Agents

The agent loop

An agent calls the model, runs the tools it asks for, sends the results back, and repeats until the model answers. The loop is a plugin itself (loop_default), so you can replace it.

res, _ := agent.Generate(ctx, "Research and summarize X",
	eipagent.MaxSteps(10),                // default 20
	eipagent.StopOnTool("submit_report"), // finish after this tool runs
	eipagent.ToolChoice("required"),      // auto | none | required | a tool name
)

Hooks can change any step:

  • OnStepPrepare rewrites the next request: its model, messages or tools.
  • OnModelAfter can end the run with sc.Jump = "end".

See Lifecycles for the exact order.

Agents

Subagents and handoffs

A subagent is called as a tool and returns an answer. A handoff gives the conversation to another agent for the rest of the thread.

agent, _ := eipagent.New(
	eipagent.WithModel("openai:gpt-4.1"),
	eipagent.WithPlugins("tool_time"),
	eipagent.WithPlugin("agents", map[string]any{"agents": []any{
		map[string]any{"name": "researcher", "description": "Finds facts",
			"instructions": "Research carefully.", "tools": []any{"current_time"}},
		map[string]any{"name": "billing", "description": "Invoices and refunds",
			"instructions": "You are billing support.", "mode": "handoff"},
	}}),
)

A whole agent, with its own plugins, model and policy, can also become a tool:

legal, _ := eipagent.New(eipagent.WithModel("anthropic:claude-sonnet-5-5"), eipagent.WithProfile("legal.json"))
main, _ := eipagent.New(eipagent.WithModel("openai:gpt-4.1"),
	eipagent.WithTools(legal.AsTool("legal_expert", "Answers legal questions")))

Agents

Lifecycles

Everything in eipagent follows a fixed lifecycle, so you always know what happens and in what order.

Agent

stateDiagram-v2
    [*] --> Configuring: New(opts...)
    Configuring --> Loading: preset, policy, profiles, lock resolved
    Loading --> Ready: every plugin ACTIVE or PENDING
    Loading --> [*]: any plugin refused or FAILED → New returns the error
    Ready --> Ready: Generate / Stream / Thread runs (concurrently)
    Ready --> Ready: Load / Reload / Unload plugins, hot reload
    Ready --> Closed: Close()
    Closed --> [*]
  • New loads plugins in a fixed order:
    1. Plugins the policy requires: audit, policy and secrets.
    2. Built-in defaults.
    3. Your plugins.
    4. The provider implied by the model.
    If any plugin is refused or fails, everything already loaded is rolled back and New returns the error. You never get a half-configured agent.
  • Ready: the agent is safe to use from many goroutines at once. Each run works with the plugins that were loaded when it started.
  • Close unloads plugins in reverse order, which destroys sandboxes, stops background jobs and MCP processes, and closes databases. Calling it twice is safe.

Run

sequenceDiagram
    participant App
    participant Runner as loop plugin
    participant Hooks as middleware & hooks
    participant LLM as llm provider
    participant Tool
    App->>Runner: Generate(prompt) (snapshot of plugins taken)
    Runner->>Hooks: agent/start  (may refuse the run)
    loop each step, up to max_steps
        Runner->>Hooks: step/prepare (rewrite model, messages, tools)
        Runner->>Hooks: model/wrap ⟶ retry ⟶ fallback ⟶ pii ⟶ …
        Hooks->>LLM: Generate (streaming chunks → events)
        Runner->>Hooks: model/after (inspect, may Jump: end | model)
        alt no tool calls
            Runner-->>App: finish "stop"
        else tool calls
            Runner->>Hooks: tool/wrap ⟶ policy ⟶ audit ⟶ review ⟶ hitl ⟶ …
            Hooks->>Tool: Run(args)
            Note over Runner: an interrupt pauses the run → finish "interrupted"
        end
    end
    Runner->>Hooks: agent/end (always runs, even on error)
    Runner-->>App: Result

agent/end runs exactly once for every run that started, even when it fails. In that case the finish reason is "error". Plugins can always clean up.

Thread

stateDiagram-v2
    [*] --> Empty
    Empty --> Running: Generate
    Idle --> Running: Generate
    Running --> Idle: saved (version n+1)
    Running --> Waiting: interrupt → saved with pending calls
    Waiting --> Running: Resume(decisions)
    Waiting --> Waiting: Generate refused until Resume
    Running --> Conflict: another writer saved first
    Conflict --> [*]: ErrThreadBusy (retry)

Saves use version numbers. If two processes write the same thread at once, the second gets ErrThreadBusy instead of overwriting the first.

Plugins

Everything is a plugin

The core engine has no features of its own. It loads plugins, connects the services they provide, and calls their hooks in order. A plugin is one Go file, interpreted at runtime, or a compiled Go value with the same shape.

Apply

A function that registers tools, services, hooks and background work.

Inject

Services the plugin needs. It waits as PENDING until they exist.

Permissions

Capabilities it may use. Imports outside them are refused.

Dispose

On unload, everything it registered is undone automatically.

A plugin moves through these states:

PENDING→ LOADING→ ACTIVEor FAILED 
stateDiagram-v2
    [*] --> Refused: trust gate says no (not allowed, unpinned, hash mismatch, import not permitted)
    [*] --> PENDING: Load (compiled)
    PENDING --> LOADING: every Inject dependency exists
    LOADING --> ACTIVE: Apply returned nil
    LOADING --> FAILED: Apply errored or panicked (everything it registered is rolled back)
    ACTIVE --> PENDING: a dependency disappeared (disposed)
    ACTIVE --> ACTIVE: an optional dependency changed (restarted)
    ACTIVE --> [*]: Unload / Close (disposed)
    ACTIVE --> ACTIVE: Reload / Load with new config (new version replaces old, dependents restart)

Plugins

Writing a plugin

Put a file in a plugin directory. There is nothing to compile: the engine interprets it with Yaegi.

//go:build ignore

package plugin

import (
	"context"

	"eipagent/sdk"
)

var Inject = []string{"store"}     // wait for a store service ("?x" = optional)
var Permissions = []string{"net"}  // net, exec, fs:read, fs:write, env, db

func Apply(ctx *sdk.Context) error {
	hours := ctx.ConfigString("hours", "Mon-Fri 9:00-17:00")

	ctx.AddTool(sdk.Tool{
		Name:        "office_hours",
		Description: "Returns the office opening hours",
		Schema:      sdk.Object(map[string]any{}),
		Meta:        map[string]any{"readonly": true},
		Run: func(c context.Context, args map[string]any) (string, error) {
			return hours, nil
		},
	})

	ctx.Effect(func() func() {
		// start background work here
		return func() { /* stop it: runs on unload, reload and Close */ }
	})
	return nil
}
agent, _ := eipagent.New(
	eipagent.WithModel("openai:gpt-4.1"),
	eipagent.WithPluginDir("plugins"),
	eipagent.WithPlugin("office", map[string]any{"hours": "Mon-Sat 8:00-20:00"}),
)

Permissions a plugin can ask for:

netexecfs:readfs:writeenvdb

A plugin that imports net/http without asking for net is refused before it runs. unsafe, syscall and os.Exit are never available.

Secure preset

By default, a plugin file must match a pin in eip.lock. Run eip plugin pin -plugins ./plugins after each edit. During development, use eipagent.WithPreset("dev"), which skips pins and reloads files on save.

A compiled plugin has the same shape. Use one when the code needs third-party packages:

p := eipagent.Plugin{Name: "crm", Inject: []string{"store"}, Apply: func(ctx *eipagent.PluginContext) error {
	ctx.AddTool(crmLookupTool)
	return nil
}}
agent, _ := eipagent.New(eipagent.WithModel("openai:gpt-4.1"), eipagent.WithCompiledPlugin(p))

Plugins

Plugins at runtime

You can add, update and remove plugins while the agent is running. Each run keeps the plugins it started with, so a change never lands halfway through a run.

eng := agent.Engine()

eng.Load(eipagent.PluginSpec{Use: "tool_time"})               // add
eng.Load(eipagent.PluginSpec{Use: "office"})                  // add a new file from a plugin dir
eng.Load(eipagent.PluginSpec{Use: "office",
	Config: map[string]any{"hours": "24/7"}})                 // update its config
eng.Reload("office")                                          // update its code from the file
eng.Unload("office")                                          // remove it and everything it registered

for _, s := range agent.Status() {
	fmt.Println(s.String()) // name, state, source, permissions, what it waits for
}
  • Dependents follow. Unloading a store sends memory_store back to PENDING, and its tools disappear until a store returns.
  • Broken updates are refused. If a new version fails to compile or start, the old one keeps running.
  • Locked plugins from the admin policy can't be unloaded or replaced at runtime.
go run ./examples/ollama -demo plugins   # watch it live with a local model

Plugins

Middleware

Middleware wraps every model call and every tool call. The standard pack is configured as plugins:

agent, _ := eipagent.New(
	eipagent.WithModel("anthropic:claude-sonnet-5-5"),
	eipagent.WithPlugin("mw_retry", map[string]any{"max_retries": 3}),
	eipagent.WithPlugin("mw_fallback", map[string]any{"models": []any{"openai:gpt-4.1"}}),
	eipagent.WithPlugin("mw_limits", map[string]any{"model_calls_run": 20, "tool_calls_run": 50}),
	eipagent.WithPlugin("mw_pii", map[string]any{"types": []any{"email", "credit_card"}}),
	eipagent.WithPlugin("mw_summarize", map[string]any{"trigger_messages": 40, "keep_messages": 10}),
)

To write your own, register a wrapper. Call next to continue, or return without calling it to stop the call.

guard := eipagent.Plugin{Name: "guard", Apply: func(ctx *eipagent.PluginContext) error {
	ctx.WrapModel(func(c context.Context, req *eipagent.ModelRequest, next eipagent.ModelHandler) (*eipagent.ModelResponse, error) {
		resp, err := next(c, req)
		if err == nil {
			ctx.Logf("%s step %d used %d tokens", req.Model, req.Step, resp.Usage.TotalTokens)
		}
		return resp, err
	})
	ctx.WrapTool(func(c context.Context, req *eipagent.ToolRequest, next eipagent.ToolHandler) (*eipagent.ToolResult, error) {
		if req.Call.Name == "drop_database" {
			return &eipagent.ToolResult{Content: "not allowed", IsError: true}, nil
		}
		return next(c, req)
	})
	return nil
}}

Middleware runs in priority order, highest outermost. The locked policy and audit plugins always run outside everything else. Human approval runs innermost, so automated checks decide first.

Infrastructure

Sandboxes

Sandboxes are plugins too, and they work in both directions.

The agent uses sandboxes

Shell and file tools run in a per-thread sandbox, created on first use and destroyed when the agent closes.

agent, _ := eipagent.New(
	eipagent.WithModel("openai:gpt-4.1"),
	eipagent.WithPlugins("sandbox_docker"),                                    // no network by default
	eipagent.WithPlugin("exec_sandbox", map[string]any{"provider": "docker"}),
	eipagent.WithPlugins("tool_shell", "tool_fs"),
)
res, _ := agent.Generate(ctx, "Write notes.md and count its lines")
for _, ch := range res.Changes {
	fmt.Print(ch.Diff()) // review every file the agent changed
}

Add tool_sandbox to let the model create and destroy its own sandboxes, up to a limit you set.

The agent runs inside a sandbox

agent, _ := eipagent.New(
	eipagent.WithModel("openai:gpt-4.1"),
	eipagent.WithPlugins("tool_shell", "tool_fs"),
	eipagent.WithRunIn(eipagent.RunIn{Provider: "docker", Binary: "./eip-linux"}), // GOOS=linux go build -o eip-linux ./cmd/eip
)
// same API as before: Generate, Stream, Thread, Resume

The whole agent runs in the box. Model calls come back to the host, so API keys never enter the sandbox. Your Go tools are bridged back too.

Any backend, such as Firecracker, E2B, Kubernetes or your own, plugs in by providing sdk.SandboxProvider. See examples/custom-sandbox.

Infrastructure

Persistence and scaling

The core engine is stateless and needs no database. Threads, memory, jobs and the audit log live behind plugin services. Postgres lets every replica share them:

import _ "eipagent/drivers/postgres"

agent, _ := eipagent.New(
	eipagent.WithModel("openai:gpt-4.1"),
	eipagent.WithPlugin("db_sql", map[string]any{"dsn": "secret://EIP_DATABASE_URL"}),
	eipagent.WithPlugins("checkpoint_sql", "store_sql"),
)

With this setup, any replica can serve any thread. An approval that paused on one pod can be resumed on another.

MCP, skills and the web

eipagent.WithPlugin("mcp_client", map[string]any{"servers": []any{
	map[string]any{"name": "github", "command": "github-mcp-server", "args": []any{"stdio"},
		"env": map[string]any{"GITHUB_TOKEN": "secret://GITHUB_TOKEN"}},
	map[string]any{"name": "docs", "url": "https://mcp.internal.example.com/mcp"},

eipagent.WithPlugin("skills_dir", map[string]any{"dirs": []any{"./skills"}}) // folders with SKILL.md

eipagent.WithPlugin("tool_http_fetch", map[string]any{"allow_hosts": []any{"*.wikipedia.org"}})

Skills keep prompts small. Only each skill's name and description go into the prompt, and the model loads the full instructions when it needs them. Web fetching only reaches hosts on the allowlist, and private network addresses are always blocked.

Jobs and webhooks

Infrastructure

Tracing and audit

eipagent.WithPlugin("trace_file", map[string]any{"path": ".eipagent/trace.jsonl"})
eipagent.WithPlugin("audit_jsonl", map[string]any{"path": "/var/log/eipagent/audit.jsonl"})
go run ./cmd/eip trace view .eipagent/trace.jsonl > trace.html   # timeline of every run, model call and tool call

The audit log records every plugin load, model call and tool call, including who approved what. Each line is hash-chained to the one before, so audit.Verify(path) detects any edited or deleted line.

Security

Security model

eipagent.New() starts in the secure preset. It is built in layers:

  • Trust gate. Plugin files must match a sha256 pin. Each plugin can import only what its permissions allow.
  • Locked policy. An admin policy loads last, and nothing can override it. Locked plugins always run first and can't be removed.
  • Secrets by grant. Config refers to secret://NAME. Each plugin can read only the secrets granted to it.
  • Containment. Sandboxes have no network by default, web fetching is allowlisted, and webhooks must be signed.
  • People in control. Approvals, reviewer models, limits and token budgets.
  • Evidence. A tamper-evident audit log.
Know the limit

Permission scoping inside the interpreter is defense in depth, not a hard boundary. For untrusted plugin code, run the agent in a container or microVM with WithRunIn.

Security

Admin policy

A policy file sets company-wide rules. Load it with eipagent.WithPolicyFile("policy.json").

{
  "require_pins": true,
  "hot_reload": false,
  "deny": ["sandbox_local"],
  "locked": ["policy", "audit_jsonl", "secrets_env"],
  "require": [
    { "use": "audit_jsonl", "config": { "path": "/var/log/eipagent/audit.jsonl" } },
    { "use": "secrets_env", "config": {
        "allow": ["OPENAI_API_KEY", "ANTHROPIC_API_KEY"],
        "grants": { "llm_openai": ["OPENAI_API_KEY"], "llm_anthropic": ["ANTHROPIC_API_KEY"] } } },
    { "use": "policy" }
  ],
  "rules": {
    "mode": "workspace-write",
    "require_sandbox": true,
    "allow_models": ["anthropic:*", "openai:gpt-4.1*"],
    "deny_tools": ["*__delete_*"],
    "max_tokens_run": 400000,
    "roles": { "analyst": { "mode": "read-only" } }
  }
}

Modes: read-only allows only read-only tools. workspace-write is the default. full-access allows high-risk tools. Roles come from eipagent.WithUser(id, roles...).

Result and events

type Result struct {
	Text         string
	Steps        []sdk.Step      // Response, ToolResults, Usage, Finish
	Usage        sdk.Usage       // InputTokens, OutputTokens, TotalTokens
	FinishReason string          // stop | max_steps | interrupted | tool:<name>
	Interrupts   []sdk.Interrupt // ID, Kind, ToolCall, Message, Allowed
	Messages     []sdk.Message   // full history
	Thread       string
	Changes      []Change        // files written by tool_fs; Change.Diff()
}
